# docs-src 编写规范

## 一、定位

`docs-src/` 是仓库根目录下的规范文档来源，覆盖**整个工作区**内所有需维护的模块（含 `tests/`、`examples/`），供维护者与 coding agent 在改代码前查阅、在改代码后同步更新。

`docs-src/` **仅含 Markdown**，是文档镜像层，不是源码副本。

## 二、镜像范围与排除

### 镜像规则

对仓库内任意源路径 `<P>`（相对仓库根），其文档镜像路径为：

```text
docs-src/<P>/
```

目录层级须与源树**精确一致**；叶级 `.md` 文件名可合并或拆分，但**不得**改变目录结构。

`tests/` 与 `examples/` 同样适用：`docs-src/tests/...` 镜像 `tests/...` 的文档，不替代其中的 pytest 代码。

### 排除

1. 以 `.` 开头的目录及其子路径。
2. 根目录 `.gitignore` 已忽略的路径。
3. `docs-src/` 自身不无限嵌套；横切规范放在 `docs-src/guide-references/`。

### 每个重要目录至少具备

- `INDEX.md`：镜像来源路径、职责、关键入口。
- 按需专题 `.md`。
- 六要素（见第三节）。

## 三、文档内容要求

每篇文档高信息密度，**至少覆盖**：

1. **目的**
2. **导出项**（公共 API）
3. **核心逻辑**（数据流 / 状态机）
4. **依赖关系**
5. **约束与陷阱**
6. **交互方式**（编译目标、HTTP、终端等）

禁止：大段粘贴源码、填充废话、emoji。

## 四、查阅规则（改代码前）

修改源码或测试**之前**，必须先读 `docs-src/` 中与源路径对应的文档。

映射：源文件 `<P>/file` → `docs-src/<P>/` 下相关 `.md`。

以 docs-src 为第一参考；已有充分文档时，不得用大范围源码扫描代替。

## 五、更新规则（改代码后）

凡改变**可观察行为**的变更，须同步更新受影响的 `docs-src/` 文档。

## 六、索引

- 工作区入口：`docs-src/INDEX.md`
- 测试分工：`docs-src/tests-guide.md`
- 代码与禁词：`docs-src/guide-references/code-guide.md`

## 七、与 Agent 内部文档的分工

| 位置 | 用途 | 是否进 `.py` |
|------|------|-------------|
| `.claude/docs/` | 阶段执行、总控、追踪矩阵（仅 agent） | 禁止引用 |
| `docs-src/` | 模块镜像、测试说明、贡献者规范 | 禁止引用 |
| `docs/`（若保留） | 对外用户文档入口，链到 docs-src | 禁止引用 |

规格章节编号、阶段文件名、矩阵表名等**不得**出现在 `echoui/`、`tests/`、`examples/` 的注释与 docstring 中。
